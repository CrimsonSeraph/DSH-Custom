# Web UI 专项规范

适用：营销网站、内容站、SaaS、Web 应用、响应式页面。

## 1. 布局与导航
- 移动宽度优先思考，再扩展到平板与桌面；断点应由内容布局需要决定，而不是机械追随设备型号。
- 顶部导航、侧边栏或应用内导航应保持稳定，当前所在位置清晰。
- 提供明确的返回路径；避免让用户依赖浏览器后退才能理解导航关系。
- 正文设置可读的最大宽度；长文本不应无限拉宽。
- 页面结构由任务决定：内容站优先阅读与发现，后台优先数据与操作，工具优先工作区域。

## 2. 响应式行为
- 不只缩放元素；根据视口改变信息优先级、排列顺序、导航方式和操作入口。
- 检查窄屏下的长标题、长单词、表格、菜单、弹窗和表单。
- 不要用 `overflow: hidden` 掩盖重要内容被截断的问题。
- 图片按用途设置合理比例与裁切；避免加载巨大、未经优化的资源。
- 注意键盘焦点、浏览器缩放、软键盘和系统字体缩放。

## 3. 组件与状态
- 表格应支持合理的横向适配、字段优先级、空状态和加载状态。
- 弹窗只用于需要聚焦或确认的任务；不要把每个流程都放进模态框。
- 固定页头、浮动按钮和粘性元素不能遮挡主要内容或焦点。
- 表单验证应就地显示，且在提交后提供清晰的错误汇总（复杂表单适用）。
- 对导航、按钮和链接使用正确的语义元素。

## 4. Web 体验自检
- 在窄屏、常见桌面宽度和缩放状态下检查布局。
- 检查键盘导航、焦点可见性、链接语义和错误状态。
- 确认加载、空、失败与成功状态不会导致页面跳动或信息丢失。
- 检查页面标题、层级结构和表单标签是否清晰。
