# Mobile App UI 专项规范

适用：iOS、Android 及跨平台移动应用。

## 1. 安全区与触控
- 为刘海、圆角、状态栏、底部系统手势区域预留安全空间。
- 触控目标通常至少以 44×44 pt/CSS px 作为实用基准，并遵循目标平台规范；相邻控件之间留出足够间距。
- 不把重要操作仅隐藏在手势里；应提供可发现的可见入口。
- 避免把桌面端密集表格直接缩放塞进手机。

## 2. 导航与页面结构
- iOS 通常遵循导航栈、系统返回手势和常见底部 Tab 习惯。
- Android 可根据信息架构选择底部导航、顶部导航或导航抽屉。
- 导航项数量应服务于核心任务，不要把每个功能都放进底部导航。
- 页面应清楚展示当前位置、返回方式和当前任务状态。
- 在小屏上重新排序信息，而不是简单隐藏溢出内容。

## 3. 表单与输入
- 尽量减少输入步骤，合理使用自动填充、选择器和合适的键盘类型。
- 软键盘出现时，当前输入框、错误提示和主要操作不应被遮挡。
- 错误应就地说明；尽可能保留用户已输入的有效内容。
- 对长流程显示进度或步骤位置，并支持合理的返回与继续操作。

## 4. 动效与系统适配
- 动效短且有目的，尊重减少动态效果偏好。
- 适配字体缩放、横竖屏（适用时）、高对比度和系统主题。
- 避免依赖悬停表达重要信息。
- 网络慢或离线时，应提供可理解的反馈与恢复方式。

## 5. 移动端自检
- 检查安全区、软键盘、触控目标、滚动与返回行为。
- 检查小屏、长文本、大字体和加载失败场景。
- 确认主要操作不会被手势区域、固定栏或弹窗遮挡。
