# 仪表盘与数据密集型界面专项规范

适用：SaaS 后台、管理控制台、数据分析、运营工具和企业应用。

## 1. 先定义数据任务
先确定用户要监控、比较、筛选、诊断还是执行操作。信息架构应围绕这些任务组织，而不是默认用统计卡片填满首屏。

## 2. 数据层级
- 关键指标应有明确上下文：名称、单位、时间范围、比较基准和必要说明。
- 图表应服务于具体问题；不要为了视觉丰富而加入无意义图表。
- 表格列应对齐，数值格式一致；排序、筛选、分页和批量操作应有清晰反馈。
- 使用语义化状态颜色，但不能只靠颜色传达含义。
- 不伪造示例数据或把占位值伪装成真实业务数据。

## 3. 密度与导航
- 允许比消费类界面更高的信息密度，但应通过分组、对齐和留白保持可扫描性。
- 筛选器应显示当前条件，并能方便清除或调整。
- 批量操作应明确作用范围、选中数量和执行结果。
- 高级筛选和低频设置可以折叠，但不能隐藏关键条件。
- 在窄屏下重新设计字段优先级或详情查看方式，不要直接压缩桌面表格。

## 4. 状态与可信度
- 明确数据更新时间、加载状态、无数据和数据获取失败。
- 对空结果区分“没有数据”“筛选后没有结果”和“加载失败”。
- 对可能延迟或不完整的数据说明状态，避免给用户造成确定性错觉。
- 图表应有清楚标题、轴标签、单位和必要的文本替代说明。

## 5. 仪表盘自检
- 用户是否能迅速找到最重要的数据与下一步操作？
- 指标是否有单位、时间范围和比较依据？
- 表格、筛选和批量操作是否可理解？
- 空数据、异常值、长标签和窄屏是否处理妥当？
