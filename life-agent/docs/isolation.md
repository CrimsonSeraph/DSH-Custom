# 执行面隔离边界（虚拟桌面 / Android 模拟器 / microVM）

本文规定生活型 Agent 三个执行面（下称「身体」）各自的定位、相互之间的硬性边界、权限与凭证约束，
以及失败与失控时的降级顺序。后续插件阶段与运行期操作都以此文为准；本文只描述边界，不记录任何凭证。

## 1. 三个执行面的定位

| 执行面 | 提供方 | 对外能力 | 可见性 | 本阶段状态 |
| --- | --- | --- | --- | --- |
| Win32 虚拟桌面 | dsh-vdesktop | `vdesk_*` 工具族，在独立的虚拟桌面里启动并驱动 GUI 程序 | 用户看不见；可在 Web GUI 的 VDesktopPanel 中观看并接管 | 计划启用 |
| Android 模拟器 | dsh-dot | `mcp__phone__*` 工具，经 ADB 操控模拟器；同时承载 IM 接入 | 由模拟器窗口自身决定，不并入虚拟桌面 | 计划启用 |
| microVM | dsh-dot 的 `computer` 组件 | 独立机器镜像内的完整环境 | 可选 | 本阶段不启用 |

### 1.1 Win32 虚拟桌面（dsh-vdesktop）

- 执行面是一个与当前交互桌面并行的 Win32 桌面：桌面上的窗口不会出现在用户正在使用的屏幕里，也不会抢焦点。
- Agent 通过 `vdesk_*` 工具族在该桌面内启动程序、点击、输入、读屏；具体工具名与参数以插件阶段核实的实际注册结果为准（待插件阶段核实）。
- 用户观察与介入的入口是 Web GUI 的 VDesktopPanel：可以在其中看到该桌面的实时画面，并用自己的真实鼠标接管。
- 该执行面的用途是「有 GUI、但不能干扰用户」的桌面程序：文档处理、桌面客户端、需要窗口的本地工具等。

### 1.2 Android 模拟器（dsh-dot）

- 执行面是一台 Android 模拟器实例，Agent 通过 `mcp__phone__*` 工具族经 ADB 操控（安装应用、点击、滑动、输入、截屏、读取界面）。
- 同一组件的 IM 接入负责「主动联系」：它把会话延伸到消息通道，使 Agent 能在用户不在终端前时发出消息、接收回复。
- IM 接入与模拟器是同一个插件里的两条通道，但**通道独立**：IM 不通不影响模拟器，模拟器不可用也不影响 IM 收发。
- 账号绑定与凭证只按第 4 节的尺度记录（只记账号类型）。
- 具体工具名、可用的 IM 平台范围、模拟器镜像来源以插件阶段核实为准（待插件阶段核实）。

### 1.3 microVM（dsh-dot 的 computer 组件）

- 定位是「可选加强项」：当需要比宿主进程更强的隔离（独立文件系统、独立网络栈）时才考虑启用。
- 本阶段不启用；本文只登记它的边界位置，不描述其安装与运行细节（待插件阶段核实）。
- 未启用时，其余两个执行面的行为不受影响；启用与否是运行期开关，不是插件安装的必选项。

## 2. 硬性边界

1. **并行、独立，互不嵌套。**
   - Android 模拟器与虚拟桌面是两个并行的「身体」，各自持有自己的进程、窗口与输入通道，任何一方都不作为另一方的子窗口或在另一方的输入通道内运行。
   - **禁止把 Android 模拟器窗口塞进隐藏的虚拟桌面**：既不在 `vdesk_*` 桌面里启动模拟器，也不用虚拟桌面的点击/输入去驱动模拟器窗口。模拟器只用 `mcp__phone__*` 经 ADB 操控。
   - microVM 独立于前两者，不与虚拟桌面嵌套，也不与模拟器嵌套；三者不构成「外面套里面」的层级。
2. **不共享输入与焦点。** 任一执行面的输入事件只对自身生效；不存在「一次点击同时作用到两个身体」的路径。
3. **不共享凭证。** 各执行面使用的账号、令牌互相隔离；在一个执行面里取得的登录态不得被复制到另一个执行面复用。
4. **发现即停。** 一旦观察到两个执行面出现交叉（模拟器出现在虚拟桌面里、microVM 里的操作影响到宿主桌面），立即停止该路径并向用户报告，不要自行「修好」再继续。

## 3. 权限边界

- **所有身体都不涉及支付与消费。** 虚拟桌面、Android 模拟器、microVM 三者一致适用。
- 禁止自动执行任何会产生金钱支出或等价承诺的动作，包括但不限于：购买、下单、支付、充值、打赏、订阅、开通会员、续费、点外卖、叫车、购买应用内项目、绑定银行卡或支付方式。
- 上述动作即使用户此前说过「随便买」，也必须逐次确认；不存在一次性永久授权。
- 若某个任务的完成路径上出现支付环节，正确处理是：停在支付前的最后一步，把当前状态、待付金额、对象与替代方案交给用户，由用户本人完成。

## 4. 凭证边界

- IM 绑定账号**只记录账号类型**（例如「某 IM 平台的个人账号」「某平台的机器人账号」），以及该账号在界面上如何选取。
- **绝不记录**密码、密钥、令牌、验证码、Cookie、二维码内容、恢复码，也不记录可反推这些内容的字段（部分遮蔽的手机号、邮箱、账号 ID 视同敏感）。
- 凭证不进仓库：不写入本文档、不写入 `custom\life-agent\` 下任何文本资产、不写入 `mcp` 的配置清单、不写进 prompt 模板。运行期凭证由 DSH 的凭证/授权机制或宿主环境提供，仓库内只保留「需要哪种账号」这一层描述。
- 日志与截屏同样受此约束：分享执行面截屏或运行记录前，先确认画面里不含登录态、验证码、余额与账号标识。

## 5. 失败与失控边界

优先级固定为：**人工接管 > 自动化继续**。

1. 用户提出接管时，立即让出控制：停止正在进行的自动操作，交回画面与输入，不再自行补动作。
2. 自动化连续失败（同一目标重试无进展）、出现意料之外的界面或系统弹窗、需要跨越第 3 节或第 6 节所列动作时，主动停止并请求接管，而不是换一种方式硬试。
3. 任一执行面不可用（插件未加载、模拟器起不来、桌面创建失败、ADB 断开、IM 掉线）时：
   - **降级为纯文本对话**继续当前任务，说明缺的是哪个执行面、卡在哪一步；
   - **不阻塞其它执行面**：一个身体不可用不影响另外两个身体的正常调用；
   - 不因为某个执行面缺失而重复尝试拉起（同一会话内最多一次自愈重试，失败后报告）。
4. 任何执行面都不得在用户不知情的情况下长期常驻运行；会话结束或任务完成后释放。需要常驻的，先在运行记录里写明并由用户确认。

## 6. 必须先问用户的操作

以下动作**一律先问、得到明确同意后才执行**，且同意只对当次有效：

1. 任何支付、消费、订阅、打赏、下单、充值（第 3 节）。
2. 绑定、登录、切换、解绑任何账号，包括 IM 账号、应用账号、模拟器内的 Google/厂商账号。
3. 输入或读取任何凭证、验证码、密钥、恢复码。
4. 在 Android 模拟器里安装来自未知来源的应用、授予敏感权限（通讯录、短信、定位、无障碍、设备管理）、或修改系统设置。
5. 在虚拟桌面里启动需要管理员权限的程序、修改系统级设置、安装/卸载软件。
6. 向外部（IM 联系人、邮件、网页表单）发送任何内容，尤其是含个人信息、地址、日程、财务信息的内容。
7. 删除、覆盖已有数据（文件、邮件、聊天记录、照片），或执行不可逆操作（格式化、清空、注销账号）。
8. 启用 microVM，或改变任一执行面的隔离配置。
9. 跨执行面搬运数据（把虚拟桌面里的内容送到模拟器或 microVM，反之亦然）。
10. 用户要求接管后，请求恢复自动执行。
